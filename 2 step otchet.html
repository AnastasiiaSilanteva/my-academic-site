Что такое Git?

Git — это распределённая система управления версиями, которая позволяет отслеживать изменения в файлах и координировать работу над проектами. Она незаменима для разработки, особенно при создании статических сайтов на Hugo.

##Основные команды, которые я использовал

  • git init — создание нового репозитория.
  • git add . — добавление всех изменённых файлов в индекс.
  • git commit -m "сообщение" — фиксация изменений.
  • git remote add origin <URL> — связывание с удалённым репозиторием.
  • git push — отправка изменений на GitHub.
  • git pull — получение обновлений.

##Зачем Git нужен для сайта?

Благодаря Git я могу:

  • Отслеживать историю изменений.
  • Возвращаться к предыдущим версиям в случае ошибок.
  • Использовать GitHub Actions для автоматического деплоя.
  • Работать с ветками (например, создавать ветку dev для экспериментов).

##Заключение

Git сделал процесс разработки моего сайта прозрачным и управляемым. Даже если что-то сломается, я всегда могу откатиться к стабильной версии.

##Что такое CI/CD?

CI/CD (Continuous Integration / Continuous Deployment) — это практика автоматизации сборки, тестирования и развёртывания приложений. Для статического сайта это означает, что при каждом изменении в репозитории сайт автоматически пересобирается и публикуется на хостинге.

##Моя настройка GitHub Actions

В репозитории я создал файл .github/workflows/hugo.yaml, который выполняет следующие шаги:

  1. Checkout — клонирует репозиторий.
  2. Setup Hugo — устанавливает Hugo (extended версия).
  3. Setup Node.js — устанавливает Node.js для TailwindCSS.
  4. Install TailwindCSS — глобально устанавливает TailwindCSS CLI.
  5. Build — выполняет hugo --minify, генерируя статические файлы в папку public.
  6. Upload artifact — сохраняет папку public как артефакт.
  7. Deploy — публикует артефакт на GitHub Pages.

Вот фрагмент файла:

name: Deploy Hugo site to GitHub Pages
on:
  push: { branches: ["main"] }
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: peaceiris/actions-hugo@v2
        with: { hugo-version: 'latest', extended: true }
      - uses: actions/setup-node@v4
        with: { node-version: '20' }
      - run: npm install -g tailwindcss
      - run: hugo --minify
      - uses: actions/upload-pages-artifact@v3
        with: { path: ./public }
  deploy:
    environment: github-pages
    runs-on: ubuntu-latest
    needs: build
    steps:
      - uses: actions/deploy-pages@v4

Преимущества автоматического деплоя

Экономия времени — не нужно вручную загружать файлы. Надёжность — каждый деплой выполняется в чистом окружении. Версионность — можно отследить, какие изменения привели к публикации. Заключение

Благодаря CI/CD мой сайт обновляется автоматически при каждом пуше в репозиторий. Это идеальное решение для статических сайтов, где важно быстро доставлять изменения читателям.
